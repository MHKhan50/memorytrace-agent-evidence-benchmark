# Publication checklist

- [ ] Run the exact commands in README on the intended machine.
- [ ] Confirm all tests pass and inspect `outputs/summary.csv` and `coverage_vs_risk.svg`.
- [ ] Re-run at multiple seeds and scenario counts; report variability, not only one seed.
- [ ] Review whether the synthetic assumptions unfairly favour a policy; add ablations.
- [ ] Complete a literature review before claiming novelty.
- [ ] Replace the Results placeholder in `article_draft.md` with actual output values and seed.
- [ ] Keep the “synthetic benchmark” label in the article, dataset card, and repository description.
- [ ] Publish the code to GitHub only after reviewing files and licence.
- [ ] Add a website article and listing entry; verify the live URL returns HTTP 200.
- [ ] If appropriate, deposit a fixed release on Zenodo/OSF/Figshare and cite the resulting DOI only after deposit.
- [ ] Optionally use Google Search Console URL Inspection to request crawling after the article is live. A request does not guarantee indexing; indexing is not certification.
- [ ] Consider Kaggle only if a notebook or dataset card adds real reuse value; cross-posting is not mandatory.

# MemoryTrace: A Synthetic Benchmark for Evidence-Aware Agent Memory

**Research question:** In a multi-step AI-assistant workflow, how do retrieval policies trade off answer coverage against stale, unsupported, or non-consensual memory use?

MemoryTrace is a small, deterministic, dependency-free benchmark for testing *retrieval and evidence gates* before connecting a real LLM. It is designed for undergraduate/MSc/MRes reproducibility work and as a starting point for a PhD-scale study—not as evidence that a real LLM agent is safe.

## Quick start (macOS; Python 3.9+)

From the extracted project folder, run:

```bash
python3 run_benchmark.py && python3 -m unittest discover -s tests -v
python3 plot_results.py
```

No pip install, network access, model download, API key, or cloud service is required. The first command regenerates the synthetic scenarios, evaluates all policies, writes CSV/JSON outputs, and runs tests. The second creates `outputs/coverage_vs_risk.svg`.

## What is evaluated?

Four policies are compared on the same generated scenarios:

1. `keyword_only`: selects the highest lexical-match candidate, ignoring evidence and consent.
2. `latest_relevant`: selects the most recent candidate marked relevant, without provenance or consent gates.
3. `provenance_gate`: requires a relevant candidate, a verified source, consent, and an unexpired record.
4. `strict_evidence`: applies the provenance gate and a higher evidence-quality threshold; it may abstain more often.

Metrics include answer accuracy among answered queries, coverage, overall correct-answer rate (abstentions count as not correct), stale-selection rate, unsupported-selection rate, and non-consensual-selection rate. Rates are calculated over all scenarios unless the metric explicitly says “among answered”.

## Research use

- Change seeds, scenario count, candidate generation probabilities, and policy thresholds.
- Add an LLM-backed retriever as a separate experimental arm, recording model name/version, prompt, decoding settings, and runtime.
- Report per-condition confidence intervals and perform ablations before making claims.
- Preserve the synthetic-data label. These examples are generated, not collected from users or a public corpus.

## Reproducibility and interpretation

`outputs/summary.csv` and `outputs/summary.json` are generated by the code; do not treat example outputs as externally validated findings. Synthetic rules encode the benchmark assumptions, so policy rankings may change when those assumptions change. A verified source flag is an oracle label in this simulation, not a real-world verification service. Consent and expiry are also simulated.

## Files

- `benchmark.py` — generator, policy logic, metrics, output writer.
- `run_benchmark.py` — one-command experiment runner.
- `generate_dataset.py` — regenerate only the synthetic dataset.
- `plot_results.py` — standard-library SVG graph generator.
- `data/scenarios.csv` — generated candidate-level data.
- `outputs/episode_results.csv` — per-scenario/policy decisions.
- `outputs/summary.csv`, `summary.json` — aggregated results.
- `tests/` — unit tests.
- `article_draft.md` — cautious article draft.
- `dataset_card.md`, `research_context.md`, `references.md` — provenance and research framing.
